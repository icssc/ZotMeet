## Local Development

### Prerequisites

- [Git](https://git-scm.com/downloads)
- [Node.js](https://nodejs.org/en/)
- [pnpm](https://pnpm.io)
  - Just run `npm i -g pnpm` to install.
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) 

### Local Setup

1. Clone this repository locally
2. Navigate to the root directory and install the dependencies.
   1. `cd ZotMeet`
   2. `pnpm install`
3. Copy the example environment file:
   ```bash
   cp .env.example .env
   ```
4. Make sure Docker Desktop is running, then set up the database:
   ```bash
   pnpm db:setup
   ```
5. Start the development server
   1. `pnpm dev` (run `pnpm dev --host` if you want to access the server from other devices on your network)
6. The app should be viewable at `localhost:3000` by default.

### Mobile app (Expo)

`apps/mobile` is the React Native client (Expo Router). It mirrors the web app's structure, shares its colour tokens (`packages/tokens`) and domain helpers (`packages/shared`), and talks to the same database through the web app's `/api` routes. It does not replace the PWA.

Start the Expo bundler in a second terminal while `pnpm dev` is running for the web app and `/api` routes:

```bash
pnpm mobile
```

That starts the Expo bundler. From the terminal, press `i` (iOS Simulator), `a` (Android emulator), or `w` (web preview), or scan the QR code with [Expo Go](https://expo.dev/go) on a physical device (same Wi-Fi as your machine). More detail lives in `apps/mobile/README.md`.

### Seeding the Database (for Testing)

The seed script (`src/db/seed.ts`, helpers in `src/db/seed/`) fills your **local** database with fake users, groups, future-dated meetings and random availabilities, so you can exercise the dashboard, group pages and availability grid without real accounts. It writes straight to the database, so it sends no email, and it refuses to run against anything but `localhost` (including connection strings that use `?host=` to point elsewhere).

```bash
pnpm db:seed                                  # 3 groups, 4 meetings each
pnpm db:seed --groups 5 --meetings 3          # shape the data
pnpm db:seed --user you@example.com           # see it from your own account
pnpm db:seed --help                           # every flag
```

| Flag | Default | Meaning |
|------|---------|---------|
| `--groups N` / `--meetings N` | 3 / 4 | groups, and meetings per group |
| `--users N` / `--members N` | 20 / 8 | fake user pool, and members per group |
| `--days N` / `--max-dates N` | 14 / 4 | normal meetings fall 1..N days ahead, with up to `--max-dates` dates each; days-of-the-week meetings ignore both and use the app's fixed 2023 weekday dates |
| `--from HH:MM` / `--to HH:MM` | random preset | meeting window (Pacific time) |
| `--archived F` / `--scheduled F` / `--days-of-week F` | 0.1 / 0.25 / 0.15 | per-meeting probability of each state; the rest are unscheduled |
| `--user EMAIL` | none | add this account to every group, host some meetings, and send it invite notifications for the other non-archived ones |
| `--seed N` | random | reproduce a run; the seed is printed each time |
| `--append` | off | keep earlier seeded data instead of wiping it first |

- **Re-runs are clean by default.** Seeded rows are tagged with a `seed_` user id prefix, and a normal run first deletes all earlier seeded data (from every earlier run, including appended ones) before creating new rows. With `--append` nothing is deleted. Real accounts and everything outside the seeded groups are never touched. With `--user`, the wipe does remove your account's membership, responses and hosted meetings *inside the seeded groups*, plus the invite notifications the seed sent you.
- **`--user` needs an existing account.** Sign in to the app once first; the script finds you by email (case-insensitive) and stops before changing anything if it can't. Without it, the data exists but your account has no connection to it, so it won't appear when you're signed in.
- **Size limit.** `--groups` x `--meetings` x (`--members` + 2) is capped at 100,000 availability rows, so a huge combination fails fast with a message instead of running out of memory.
- **`--append` needs a fresh `--seed`.** User ids are derived from the seed, so reusing one is refused instead of silently skipping users.
- **Reproducible per day.** The same `--seed` and flags give the same groups, members, meetings, times and availability answers on the same calendar day. Meeting dates count forward from today, and timestamps like `created_at` and `sent_at` follow the clock, so they differ between runs. Group, meeting and member ids and invite tokens are random, but seeded user ids are built from the seed (`seed_<seed in base 36>_<name>`) and the Seed Admin's ids are fixed.
- All times are `America/Los_Angeles`. Scheduled blocks follow the schedule UI, which uses the browser's clock, so they only line up exactly if your machine is also on Pacific time.

## Progressive Web App / iOS App Store

ZotMeet ships as an installable PWA and is packaged for the Apple App Store
through [PWA Builder](https://www.pwabuilder.com/).

### What's wired up

- **Web App Manifest** at `/manifest.webmanifest` (generated by
  `src/app/manifest.ts`) with `name`, `short_name`, `description`, `start_url`,
  `display: standalone`, `background_color`, `theme_color`, `icons` (any +
  maskable, including a 512x512), `shortcuts`, `categories`, `screenshots`,
  `prefer_related_applications`, `related_applications`, `launch_handler`,
  `scope_extensions` (Google OAuth host), and optional `iarc_rating_id`.
- **Service worker** at `public/sw.js` (network-first navigations, cache-first
  for static assets, offline fallback at `public/offline.html`). Registered via
  `public/sw-register.js` in production.
- **Apple meta tags** (`apple-mobile-web-app-capable`,
  `apple-mobile-web-app-status-bar-style`, `apple-touch-icon`) emitted via
  `metadata.appleWebApp` and `metadata.icons` in `src/app/layout.tsx`.
- **Security headers** (`Strict-Transport-Security`, `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`) in
  `next.config.mjs`.
- **Icons** generated from `public/zotmeet-logo.svg` via
  `pnpm pwa:icons` (uses `sharp`). Output goes to `public/icons/` and
  `public/apple-touch-icon.png`.
- **`robots.txt`** and **`sitemap.xml`** at the site root.

### Configuring the production URL

PWA Builder requires the manifest's URLs to be absolute and reachable over
HTTPS. Deployments set `NEXT_PUBLIC_BASE_URL` per stage in `sst.config.ts`
(e.g. `https://zotmeet.com` in production). That same variable drives Open
Graph, robots, sitemap, and invite/email links.

### Packaging for the iOS App Store

1. Deploy the app to its public HTTPS URL.
2. Visit [pwabuilder.com](https://www.pwabuilder.com/) and enter the URL.
3. Set `PWA_IARC_RATING_ID` after completing the free IARC questionnaire through
   a participating storefront (see [How IARC Works](https://www.globalratings.com/how-iarc-works/)).
   Update `NEXT_PUBLIC_IOS_BUNDLE_ID` if PWA Builder assigns a different bundle ID.
4. Click `Package for stores` → `iOS` → `Generate Package`.
5. Take note of the `Bundle ID` and download the package.
6. Open the generated `.xcworkspace` in Xcode (≥ iOS 17 SDK), run
   `pod install` in `src/`, build, and archive for distribution following the
   [PWA Builder iOS guide](https://docs.pwabuilder.com/#/builder/app-store).

### Regenerating PWA assets

```bash
pnpm pwa:icons
```

Regenerates icons under `public/icons/` and store screenshots under
`public/screenshots/`.

This re-renders all icon sizes (`72`–`1024`), maskable icons (`192`, `512`),
the Apple touch icon (`180x180`), and favicons from `public/zotmeet-logo.svg`.
Commit any changes under `public/icons/` and `public/apple-touch-icon.png`.
